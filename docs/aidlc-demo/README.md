# AI-DLC × Kiro Crew demo · 第一版：接手前后

这个仓库的 `main` 是一个已经能用的 IM（服务端、网页、安卓）。第一版 demo 拿它做"接手前"：由一支 AWS AI-DLC 专家 agent 团队在 Kiro Crew 上按 14 条企业规范接手改造，再用同一套检查量一次"接手后"。

想说明的是：模型已经很强，看上去优质的软件信手拈来；但企业要真正 scale，需要定制的私有软件标准、安全规范，以及维护、二开、接手的检查。用 Kiro Crew 结合 AI-DLC 方法论，能很快把这些标准定制进来，搭成支撑开发组织转型的团队平台。

## 出处

IM 的底座是开源 IM 唐僧叨叨（TangSengDaoDao，Apache-2.0），许可和第三方声明保留在仓库里。在它上面补了朋友圈、品牌、界面和 AWS 部署。demo 讲的不是从零写一个 IM，而是一个已经能用的系统怎么被 agent 团队按企业规范接手、改到能交付。

## 结果（运行 `r1008b9c5`，2026-10-08）

| 检查组 | 接手前 | 接手后 |
|---|---|---|
| 功能护栏 AC（证明没改坏） | 38/38 | 38/38 |
| 安全 SEC | 2/23 | 23/23 |
| 合规 COMP | 0/15 | 15/15 |
| 上架 STORE | 0/6 | 6/6 |
| 合计 | 40/82 | 82/82 |

- 同一套 82 项检查，接手前、接手后各跑一次。安全、合规、上架这 44 项，从 2 项通过到全部通过。
- 评审 agent 打回 2 轮，第 3 次通过；52 次按角色的提交；墙钟 2 小时 43 分（不含停下来的时间），约 430 credits。
- **如实说明**：接手后的代码只到代码层面，服务端和安卓没有编译过、也没有重新部署；评审结论来自读代码。接手后的代码不在这个仓库里。
